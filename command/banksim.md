### 1. Download the Dataset

Download [Synthetic datasets generated by the BankSim payments simulator](https://www.kaggle.com/datasets/ealaxi/banksim1) from Kaggle and place it under `data/raw/` with a domain-specific folder:

```
data/raw/banksim/bs140513_032310.csv
data/raw/banksim/banksim.zip
```

The loader reads the CSV first and falls back to the zip when no CSV exists. Each dataset should be organized in its own folder under `data/raw/` to support multiple datasets from different domains.

Dataset paths, column names, thresholds, and split fractions are defined in `src/lstm_autoencoder/config.py`.

### 2. Inspect the Dataset

Run the comprehensive dataset inspection pipeline:

```Shell
uv run python -m lstm_autoencoder inspect-data --dataset banksim
```

The exploratory (BankSimDatasetExploratory) performs the following operations:

- **Entity cardinality**: Number of unique accounts and average transactions per account
- **History distribution**: Statistics on transactions per account (min, max, median, percentiles)
- **Fraud distribution**: Total fraud transactions, accounts with fraud, and fraud by account history length
- **Fraud position**: Whether fraud appears as first, second, third, or subsequent transaction
- **History before fraud**: Number of normal transactions before fraud occurrences
- **Sequence length availability**: Accounts and sequences available for different window lengths (1, 3, 5, 10, 15, 20)
- **Temporal distribution**: Fraud rate distribution across time periods and temporal drift analysis

The command saves the following artifacts under `artifacts/`:

- `dataset_inspection.txt` - Human-readable inspection report
- `dataset_inspection.json` - Machine-readable inspection results

Optional arguments:

- `--project-root` : Project root that contains `data/raw/`. Defaults to the current working directory.
- `--dataset` : Dataset folder name in `data/raw/` (e.g., `banksim`). Required.
- `--nrows` : Read only the first N rows of the file. Defaults to all rows. Use it for a quick trial run only, because the file is not time-ordered and a partial read distorts the per-account sequence statistics.

### 3. Probe Signal Learnability

Check whether the fraud label can be learned from the available features:

```Shell
uv run python -m lstm_autoencoder probe-signal --dataset banksim
```

The signal probe (BankSimSignalProbe) trains a strong supervised model (HistGradientBoostingClassifier) and compares it with a shuffled-label control to determine if the target is learnable.

This step is critical: if the best supervised model cannot beat chance, no model (including LSTM-AE) can detect fraud in this dataset.

The command saves the following artifacts under `artifacts/`:

- `signal_report.txt` - Human-readable signal probe report
- `signal_report.json` - Machine-readable signal probe results

Optional arguments:

- `--project-root` : Project root that contains `data/raw/`. Defaults to the current working directory.
- `--dataset` : Dataset folder name in `data/raw/` (e.g., `banksim`). Required.
- `--nrows` : Read only the first N rows of the file. Defaults to all rows.
- `--max-train-rows` : Maximum number of training rows used by the probe model. Defaults to 5000.

### 4. LR and GBM Ablation Baselines

Train logistic regression and GBM ablations to evaluate the contribution of history features:

```Shell
uv run python -m lstm_autoencoder ablation --dataset banksim
```

The ablation (BaselineEvaluator) trains multiple variants and compares them:

**Linear models (LogisticRegression):**
- **full**: All features including history features (history_length, step_diff, log_amount_ratio, is_new_receiver, history_bucket)
- **no_history**: All features except history features (checks if history is just a proxy for easier signal)
- **history_only**: Only history features (isolates the lift from history-based features)
- **rolling_only**: Only the within-customer deviation features (step_diff, log_amount_ratio, rolling ratios)

**Non-linear models (HistGradientBoostingClassifier):**
- **full_gbm**: GBM on all features (non-linear control)
- **static_gbm**: GBM on the per-transaction columns only, no derived history features. `full_gbm` vs `static_gbm` shows what history is worth to a non-linear model; this is the number that decides whether a sequence model has room to add anything.

The train/val/test split is by CUSTOMER and is shared with the LSTM-AE pipeline (`evaluation/banksim/split.py`), so every BankSim number is computed on the same rows.

The command reports AUC/AP overall and per history bucket (1, 2-4, 5-9, >=10) on the test set.

The command saves the following artifacts under `artifacts/`:

- `ablation_report.txt` - Human-readable ablation report
- `ablation_report.json` - Machine-readable ablation results

Optional arguments:

- `--project-root` : Project root that contains `data/raw/`. Defaults to the current working directory.
- `--dataset` : Dataset folder name in `data/raw/` (e.g., `banksim`). Required.
- `--nrows` : Read only the first N rows of the file. Defaults to all rows.
- `--no-account-code` : Exclude account_code from features (it's a factorized ID, not behavioral).

## Staged research runbook

Each step below comes from one patch of the staged series. Run them in order; every step
prints what to look at before going on.

### Step 1 (patch 0001): customer-level split and corrected baselines

Fixes that change earlier BankSim numbers: the LSTM-AE pipeline used to split by merchant
while windows and baselines were per customer; `full_gbm_no_step` was silently a logistic
regression (and `step` was never a feature); the ablation and training used two different
splits. Re-run the ablation so every later comparison uses the corrected baselines:

```Shell
uv run python -m lstm_autoencoder ablation --dataset banksim
```

Read from `ablation_report.txt`: `full_gbm` vs `static_gbm`. If `static_gbm` is already
about as good as `full_gbm`, history adds little and the paper should say so.

Optional: run the new consistency tests (no dataset needed):

```Shell
uv run pytest tests/test_banksim_consistency.py
```

### Step 2 (patch 0002): merchant/category-aware features

`CausalFeatureBuilder` gains three causal features (customer history at strictly earlier
steps only): `is_new_merchant` (first visit to this merchant), `log_merchant_visits`, and
`log_amount_ratio_cat` (amount vs the customer's own mean in the same category). They feed
the baselines automatically. For the LSTM-AE, `data/banksim/ae_features.py` adds the
category one-hot columns and `amount_cat_z` (log-amount z-score within its category, fit on
train-normal rows only); that part is used by the pipeline from step 3.

Re-run the ablation again, so the baselines see the same information the AE will:

```Shell
uv run python -m lstm_autoencoder ablation --dataset banksim
```

Read from `ablation_report.txt`: did `full_gbm` AP move above the previous ~0.93, and did
`rolling_only` rise above the previous 0.838 AUC? `static_gbm` is unchanged by this step.

Tests (no dataset needed):

```Shell
uv run pytest tests/test_banksim_features.py
```

### Step 3 (patch 0003): LSTM-AE trains on the BankSim feature set

`BankSimModelTrainingPipeline` now builds its own input: 5 continuous features (log amount,
log step_diff, `log_amount_ratio`, `log_amount_ratio_cat`, `amount_cat_z`), `is_new_merchant`
and one one-hot column per category (21 inputs). `input_dim` is set from the data, and the
resolved `feature_columns` are written into the run's `metadata.json`. Indicators are not
standardized. `history_length` is no longer an input (at the current step it is only a
position counter the model could copy).

Smoke test (about a minute, only checks that the plumbing runs end to end; the AUC of a
2-epoch run on the first rows means nothing):

```Shell
uv run python -m lstm_autoencoder train-model --dataset banksim --nrows 100000 --window 10 --bottleneck --bottleneck-dim 16 --max-epochs 2
```

Test (needs torch, skipped otherwise):

```Shell
uv run pytest tests/test_banksim_pipeline_features.py
```

### Step 4 (patch 0004): train the single chosen config

One configuration, chosen in advance from what the earlier reports show (not tuned on
test): window 10 (99% of customers have at least 10 transactions, so windows are real, not
padding), single-vector `--bottleneck` squeezed through a 16-dimensional code (the input
is 10 x 21 values, so the model cannot learn the identity), hidden size 64 (default),
checkpoint chosen by label-free validation reconstruction loss, 3 seeds.

```Shell
uv run python -m lstm_autoencoder train-model --dataset banksim --window 10 --bottleneck --bottleneck-dim 16 --seeds 42,123,2026
```

Output: `artifacts/model/banksim/version_N_loss/lstm_ae_w10_bottleneck_z16_seed{42,123,2026}_best.pt`
and `training_report.txt` under `artifacts/report/banksim/`. Read the multi-seed summary
first: if test AUC is about 0.5 the model learned nothing useful, and the next step cannot
rescue it.

### Step 5 (patch 0004): evaluate against the GBM baseline

Use the SAME window and architecture flags as in step 4 (they select the checkpoint files):

```Shell
uv run python -m lstm_autoencoder eval-banksim --dataset banksim --window 10 --bottleneck --bottleneck-dim 16 --seeds 42,123,2026 --bootstrap 1000
```

The report (`banksim_model_evaluation.txt/json`, under `artifacts/report/banksim/model_evaluator/`) has:

- **AE only**: AUC/AP of the reconstruction error for `mean` and `last` scoring; the one
  with the higher mean validation AP is used for everything after.
- **Variant table**: `lr_train`, `gbm_train` (production baselines), `gbm_val_control`
  (same GBM fit on val, no AE error), `hybrid_gbm_val` (that GBM plus the AE error),
  `stack_ae`, and shuffled-error `null_*` controls.
- **Deltas with customer-cluster bootstrap CIs**. Primary:
  `hybrid_gbm_val_vs_gbm_val_control`. Claim an improvement only if its CI excludes 0 in
  every seed while the `null_*` rows stay near 0.

How to read the result (decide before looking, then write it down):

- `ae_only` AUC clearly above 0.5 but the primary delta CI includes 0: the AE sees fraud
  but adds nothing the GBM does not already have. Report it as a negative result on this
  dataset.
- Primary delta above 0 with CI excluding 0: report dAP first (the baseline AUC is already
  ~0.998, so AP and recall@FPR carry the signal).
- If you change anything (window, `--bottleneck-dim`, hidden size), change one thing,
  re-train, and keep every variant you tried in the paper; do not pick on test.

Tests (no dataset or torch needed):

```Shell
uv run pytest tests/test_banksim_hybrid_scoring.py
```
